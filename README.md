# MediaPlan Optimizer

MediaPlan Optimizer - итоговый проект по автоматическому медиапланированию.

Внутри есть восемь абстрактных рекламных каналов: три социальных, Programmatic, три маркетплейса и SMS. Для каждого канала задаются ограничения по объёму, стоимость инвентаря и нелинейная зависимость результата от расходов.

Проект решает две основные задачи:

- **Type A** - при заданных бюджете и сроке распределить деньги так, чтобы получить максимум кликов или конверсий;
- **Type B** - при заданном KPI и сроке найти минимальный модельный бюджет или объяснить, почему цель недостижима.

Основной режим в интерфейсе - **Calendar-aware**: бюджет распределяется не только между каналами, но и между конкретными днями кампании.

## Что умеет проект

- генерировать воспроизводимый каталог каналов по фиксированному seed;
- учитывать насыщение инвентаря и снижение отдачи при росте расходов;
- строить медиаплан по каналам и дням;
- включать и исключать отдельные каналы;
- считать reach, clicks, conversions, CTR, CR, VTR, Effective CPM, CPC и CPA;
- показывать бюджет и KPI по дням и неделям;
- объяснять недостижимые цели и предлагать более реалистичные варианты;
- сравнивать Calendar-aware план с Uniform baseline;
- работать через Streamlit на русском и английском.

Дополнительно я сделала контур для работы с фактом кампании: мониторинг plan vs fact, пересчёт оставшегося бюджета и исследовательское сравнение Static, Periodic Reoptimization, Thompson Sampling и LinUCB.

## Быстрый запуск

Нужен Python 3.11.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

### macOS / Linux

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

После запуска приложение будет доступно по адресу:

<http://localhost:8501>

## Быстро посмотреть проект

Самый короткий путь - нажать **«Запустить демо»** на обзорной странице.

Демо сразу считает Calendar-aware сценарий:

- бюджет 1,2 млн руб.;
- горизонт 21 день;
- цель - максимум конверсий;
- все каналы доступны.

Дальше можно посмотреть распределение бюджета, календарь расходов, накопление KPI и сводные метрики.

Для Type B удобно попробовать цель **10 000 кликов за 14 дней**.

Чтобы увидеть обработку недостижимой задачи, можно поставить заведомо огромную цель, например **1 трлн конверсий за один день**. Вместо пустого результата приложение покажет ограничение по ёмкости и предложит варианты изменения условий.

Если хочется посмотреть дополнительную часть проекта, после успешного плана можно начать ведение кампании, добавить синтетический или CSV-факт, открыть мониторинг и пересчитать оставшиеся дни.

## Как считается медиаплан

В общих чертах путь такой:

```text
brief
  -> OptimizationRequest
  -> каталог каналов и календарные параметры
  -> проверка достижимости
  -> оптимизатор
  -> расчёт метрик
  -> MediaPlanResult
  -> Streamlit / CSV
```

Главная идея модели - убывающая отдача.

Первые вложения в канал обычно эффективнее последующих: доступный объём постепенно выкупается, а CTR и CR немного снижаются по мере насыщения. Поэтому оптимизатор сравнивает не только среднюю стоимость канала, но и отдачу следующего рубля.

В **Uniform V1** все дни считаются одинаковыми.

В **Calendar-aware V2** оптимизируется каждая пара `канал × день` с учётом дневных факторов объёма, CPM, CTR, CR и лимита расходов.

Подробно математика, Type B, feasibility, Calendar-aware и adaptive-часть описаны здесь:

[Математическая модель и технический отчёт](docs/MATHEMATICAL_MODEL.md)

## Ограничения

Это прототип, а не модель реального рекламного рынка.

Параметры частично опираются на публичные бенчмарки, но ёмкости и часть ценовых предположений синтетические. Календарные эффекты тоже заданы как воспроизводимый сценарий, а не как измеренная сезонность.

Охват не дедуплицируется между каналами и днями. В модели нет аукционной конкуренции, причинной межканальной атрибуции и подключения к реальным рекламным API.

Adaptive-часть проверяется в синтетической среде, поэтому её результаты зависят от симулятора и настроек политик.
